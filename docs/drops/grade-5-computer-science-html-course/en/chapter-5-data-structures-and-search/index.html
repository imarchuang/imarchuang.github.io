Quick Check

When should you NOT use binary search immediately?

Misconception Fixes

  • Binary search is always better.
    It works only when data is consistently sorted.
  • Data structure only stores data.
    Structure directly impacts performance and maintenance.
  • No need to track comparisons.
    Comparison count is key evidence of efficiency.

After-class Practice

Each chapter includes 6 reinforcement tasks and 2 bonus tasks. Completion is stored locally.

Reinforcement

Reinforcement 1

Linear search worst-case comparisons for n items?

Hint

Target may be last.

Answer: n.

Why: Worst case scans all items.

Reinforcement 2

Binary search precondition?

Hint

Data organization first.

Answer: Data must be sorted by one consistent rule.

Why: Without order, elimination logic fails.

Reinforcement 3

Sorted [10,20,30,40,50], first compare for target 40?

Hint

Pick middle.

Answer: 30.

Why: Binary search starts from midpoint.

Reinforcement 4

Why is studentID->name good for key-value?

Hint

Unique key idea.

Answer: Student IDs are usually unique keys.

Why: Key-value fits unique lookup patterns.

Reinforcement 5

Can binary search miss targets on unsorted data?

Hint

True/false.

Answer: Yes.

Why: Broken ordering leads to wrong elimination.

Reinforcement 6

How should search handle not-found?

Hint

Need termination and feedback.

Answer: Stop when interval is empty and return not found.

Why: Fallback behavior is part of algorithm quality.

Bonus Challenges

Bonus Challenges 1

In 16 sorted books, binary search worst-case comparisons?

Hint

Half each round.

Answer: About 4.

Why: Halving quickly reduces search space.

Bonus Challenges 2

How to keep binary search valid with daily inserts?

Hint

Maintain invariant.

Answer: Insert by rule and keep collection sorted.

Why: Algorithm validity depends on maintained preconditions.
