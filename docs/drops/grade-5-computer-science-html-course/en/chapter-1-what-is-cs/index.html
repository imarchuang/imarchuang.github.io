After-class Practice

Each chapter includes 6 reinforcement tasks and 2 bonus tasks. Completion is stored locally.

Reinforcement

Reinforcement 1

Break 'morning check-in' into 4 explicit steps.

Hint

Use clear action verbs.

Answer: Open app -> choose class -> press check-in -> verify success message.

Why: Machines need explicit and testable actions.

Reinforcement 2

Why is 'clean the classroom' a poor machine instruction?

Hint

Can the action be interpreted uniquely?

Answer: It is too vague; rewrite as concrete actions.

Why: Vague instructions are not reliably executable.

Reinforcement 3

In IPO, scanner beep belongs to which stage?

Hint

Think output feedback.

Answer: Output.

Why: Sound is system feedback.

Reinforcement 4

Why debug one key change at a time?

Hint

Think traceability.

Answer: It keeps cause-and-effect clear.

Why: Focused changes improve diagnosis speed.

Reinforcement 5

Write one stopping condition for packing a school bag.

Hint

Must be checkable.

Answer: Stop when all timetable items are packed and zipper is closed.

Why: Stopping conditions guarantee termination.

Reinforcement 6

Give one algorithm success criterion.

Hint

Include result + constraint.

Answer: Robot delivers workbook in 6 steps without wrong group.

Why: Objective criteria make testing fair.

Bonus Challenges

Bonus Challenges 1

Write a 6-step borrowing flow with one exception branch.

Hint

Include 'book not found'.

Answer: Catalog -> shelf -> scan -> if not found log request -> confirm borrow -> record return date.

Why: Robust flows cover normal and exception paths.

Bonus Challenges 2

How would you refute 'more complex algorithm is always better'?

Hint

Use correctness and maintainability.

Answer: Value comes from correctness, clarity, and testability, not complexity alone.

Why: Simple, verifiable logic scales better.
